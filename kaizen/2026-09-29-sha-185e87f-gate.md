## Why 2: Why are there 893 unclaimed differences?

Because one kind of difference is most of them. By artefact and change (the A3 Aggregator's Pareto, from
`report.json`): 696 are `sbom` "package removed" and 12 are `sbom` "package bumped", so 708 of 893 (79%) are the
images' software bill of materials. The 696 removals are 174 distinct packages (`npm`, `corepack`, `yarn`,
`node-gyp`, `@npmcli/*`, `@sigstore/*`, `tar` 7.5.11 and the rest of npm's own dependency tree) counted once in each
of the four images. The 12 bumps are `node` 22.23.2 to 22.23.3, `tar` and `tzdata`, again once per image. The next
bars are the Paper UI rebuild (`network` 85, `dom` 33, `screenshot` 16, `focus` 15, `logs` 15): 185 in all.

## Why 3: Why did 174 packages leave every image?

The monorepo's runtime image stopped shipping a package manager. Commit
[4070315](https://github.com/tutors-sdk/tutors-mono-repo/commit/4070315d6b4f7658f072f2e3fc16cc8071910d4a) "build:
patch Debian and drop package managers from the runtime image" removes `npm`, `npx`, `corepack` and `yarn` from the
runtime stage of the `Dockerfile` (the Trivy gate failed on npm's bundled `tar` and `brace-expansion`). It reached
main with [#143](https://github.com/tutors-sdk/tutors-mono-repo/pull/143) on 2026-09-19 and is not in v16.2.2
(`caa53d0`, `git merge-base --is-ancestor` says no). It is an intended, security-positive change: the same run
reports 72 advisories gone on b (18 per image, `vulns` info hunks), and the Debian patch is the 12 bumps.

## Why 4: Why is an intended change like that unclaimed?

Because nothing tells the release how to claim a removed tool. `release/claims.yaml` on main holds 4 claims, all
for the accessibility fixes of #313 (mono-repo #364), and a claim is written in the release PR (SOP step 4), so the
forecast shows the claims the next release still owes. For this change the owed claim is awkward to write:
`claims/README.md` shows how to claim one bumped package and a framework bump by glob (`*/@sveltejs/*`), but a
removed tool takes its whole dependency tree with it, 174 packages with unrelated names, one hunk per package per
image. The precise claim is not obvious and the easy one (`*/**`) is a broad claim that needs an approver.

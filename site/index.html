Tutors release harness reports

Every report the release harness keeps, newest first. A report compares two sets of Tutors images and fails on any observable difference no claim covers. The score is informational and never changes a verdict.

Release scoreboard

Visual management over time: the six trend views (the Release Confidence Score against its bands, the eight dimensions, masks, claims, hotspots, per-file risk), the run rules that open kaizen items, and the harness's own health. The numbers behind it are scoreboard.json.

Release candidates

Release mode on each candidate the monorepo cut, against production. The verdict that gates the release.

Main to RC

Each morning, main's newest signed images judged as if main were a release candidate. A forecast, never a gate: every unclaimed diff is a claim or a fix the next release will need.

Nightly noise

Production against itself. Any diff here is noise the harness must learn to ignore; a release can only fail on a clean, fresh night.

Built from the release-records, main-preview, noise and scoreboard branches by .github/workflows/pages.yml. See Kept reports in the contract.

# Root cause, countermeasures and follow-up

The right-hand side of the sheet comes from the kaizen register.

- **Post-deploy** reads only the runs since the newest deploy. It names the release production serves, when any red began, and the root cause. A rollback from an earlier release is labelled as such.
- **Countermeasures** come from the 5 Whys. Each one says where it is **in place** and what a release must show to prove it works (**check**). The tile splits them into built and waiting on a release, not built, overdue and verified.
- **Lean terms on this sheet** explains the Lean words the page uses.

# Harness 1.57.1 (contract 1.57.0)

The content lock journey reaches main's content locks. A **patch**: the stack and one journey's course id, no engine.

## Why

The 24 Oct forecast (`sha-180700e` beside 17.0.0) failed the content lock journey (Rule 0588) on side b only: "the page shows 1 heading(s) "Topic 2"" after the lecturer locked it. With it came a console 503 on `PUT /api/courses/localhost%3A8081/locks`, "upsertLock not saved", five reader error lines, an `app_errors` row and no `tutors_content_locks` row: about a dozen of the night's 131 unclaimed differences.

The cause was the harness's stack, not main. Since mono-repo #519 (Rules 0630-0632) the reader saves a lock from its server:

1. with `PRIVATE_SUPABASE_SERVICE_ROLE_KEY`, which it answers 503 without. The signed-in reader in `compose.harness.yaml` never had one; the mono-repo's own e2e stack does (`tests/e2e-stack/compose.yaml`).
2. after it checks the actor is an educator in `https://<course id>.netlify.app/tutors.json`. The journey named its course `localhost:8081`, which that check refuses (400) because only a Netlify site id is supported.

17.0.0 writes the lock from the browser, so side a never needed either.

## What changed

- `compose.harness.yaml`: the signed-in readers get `PRIVATE_SUPABASE_SERVICE_ROLE_KEY: harness-service-role-key-not-a-real-key` (both sides, so no difference; a reader before #519 ignores it). As a `PRIVATE_*` value it is also a canary for `secrets-in-response`. They resolve `harness-rules.netlify.app` to the identity stub, and the stub gets `COURSE_ORIGIN: http://course:8081`.
- `fixtures/identity/stub.mjs`: answers `https://harness-rules.netlify.app/<path>` from `COURSE_ORIGIN`. The server certificate adds that name (regenerated from the committed test CA; `fixtures/identity/README.md`).
- `traffic/journeys/rules.ts`: a third course tag, `@course-site`: the Rule journeys' course by its Netlify id `harness-rules`. The content lock journey uses it.
- `src/collectors/browser.ts`: the browser's route for `harness-rules.netlify.app` answers the whole site from the course server, not only `tutors.json` (was `routeCoursePin`, now `routeCourseSite`).

The content lock journey's pages are now `/course/harness-rules` on both sides, where they were `/course/localhost:8081`.

No verdict, Gate or exit code rule moves.

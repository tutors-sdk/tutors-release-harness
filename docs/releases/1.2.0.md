# Harness 1.2.0 (contract 1.2.0)

A minor release. Everything in the contract is additive: a consumer written
against 1.1.0 keeps working. The contract version and the harness version are
both `1.2.0`; the full contract changelog is in
[../contract.md](../contract.md#changes). This release integrates five lines of
work: R0/R1 close-out, R3 noise burn-down enablers, R5 static image artefacts,
R5 runtime artefacts and R7 persistence abstraction.

Nothing in it has been run against Docker, a registry or the real tools. The
unit tests (417) drive every collector through an injected runner. What that
cannot prove is listed under [Pending validation](#pending-validation).

## What is new

- **Six new artefacts** (nineteen in all): `bus`, `image-manifest`, `sbom`,
  `vulns`, `runtime`, `startup`.
  - `image-manifest`, `sbom`, `vulns`: read from the images before the stacks
    start. SBOM from the cosign SPDX attestation of a pulled image, or generated
    locally (`HARNESS_SBOM_SOURCE=generate`); vulnerabilities from a pluggable
    scanner (grype by default) over that SBOM with a pinned database.
    [../images.md](../images.md).
  - `runtime`, `startup`: container posture (declared and measured from inside)
    and time to healthy over N restarts. [../modes.md](../modes.md).
  - `bus`: topics published during a journey, when a bus is configured. Groundwork
    only until a bus exists. [../bus.md](../bus.md).
- **Two new mutants** (ten in all: eight edge faults, two image-level):
  `base-swap` (expects `image-manifest`), `added-package` (expects `sbom`).
- **Noise burn-down enablers (R3)**: nightly A/A on pulled and verified images
  with the k6 load, an image cache as the Quay-outage fallback (`cached`
  provenance, DEGRADED status), the status published to the `noise` branch,
  a clean-streak ratchet, a "masks land in their own PR" CI guard (warns past
  40 masks), claim hygiene, recorded overrides of a FAIL, and the fix for
  `post-deploy.yml`, which was not valid YAML. [../noise-burndown.md](../noise-burndown.md).
- **Persistence seams (R7)**: a recorder seam under the persistence collector, a
  ledger comparison (`src/compare/ledger.ts`), a migration backend seam, a clock
  probe. Behaviour on the current Supabase stack is unchanged.
  [../harness-now.md](../harness-now.md).
- **R0/R1 close-out**: a report banner (markdown and HTML) when a side is not the
  published, verified image, now also for `cached`; reference copies of the
  monorepo's workflows under `docs/monorepo/`, held by `tests/monorepo-docs.test.ts`.

## New flags, environment variables, report fields

| Kind | Since 1.2.0 |
| --- | --- |
| Stable flags | `--image-cache` (`images ensure`), `--require-verified`, `--override-reason`, `--override-by` (`run`, `compare`) |
| Non-stable flags | `--claim-max-hunks`, `--no-runtime`, `--startup-restarts` |
| Environment | `HARNESS_CLAIM_MAX_HUNKS`, `HARNESS_SBOM_SOURCE`, `HARNESS_SBOM_CMD`, `HARNESS_VULN_CMD`, `HARNESS_VULN_DB_DIR`, `HARNESS_REQUIRE_STATIC` |
| `report.json` | `claimHygiene`, `override`, `imageArtefacts`, provenance `cached` with `cachedAt`, `noise.degraded` |
| `noise-status.json` | `degraded` |
| `masks.yaml` | optional `startup.minShiftMs` (default 250, in code; the block is commented out in the file, see below) |
| Exit code | `0` also covers a FAIL overridden with `--override-reason` |

Behaviour that changes without a flag: the new artefacts are collected on every
run. A `runtime` or `startup` artefact that could not be collected is a failing
hunk; a static image artefact that could not be collected is informational
unless `HARNESS_REQUIRE_STATIC=1`. Compare with the same tag under 1.1.0 and you
will see new hunks, not new fields; reports of different harness versions are
not comparable (contract, Compatibility).

## Decisions taken while integrating

- **Startup restarts are off in two places**: `harness mutants` (and so the
  weekly workflow) and `upgrade` mode. `harness mutants` also forces
  `HARNESS_SBOM_SOURCE=generate`, because a mutant is a local build with no
  attestation; both settings are applied together and independently. The per-PR
  smoke A/A in `ci.yml` was left as it is: it now restarts every app five times
  per side, and `--startup-restarts` is a non-stable flag, which
  `tests/contract.test.ts` forbids workflows from using. Either make the flag
  stable (a minor addition) and pass `0` there, or accept the cost and the
  flake risk; see the open decisions.
- **`startup:` block in `normalise/masks.yaml` is commented out.** An uncommented
  block is a threshold change, and `src/ci/mask-change.ts` would fail this PR,
  which changes much else, for it. The default (250) lives in
  `src/normalise/masks.ts`, so behaviour is identical. Tuning it is a
  masks-only PR.
- **The provenance banner covers `cached`** as it does `built-from-ref` and
  `pulled-unverified` (the R3 branch had a dead copy of that list in the HTML
  provenance table; the shared `loudProvenance` is the one place now).
- **"Not collected" is not uniform.** The static artefacts say `NOT COLLECTED`
  (upper case, in `reasons`, the report tables and the hunk summary) and are
  informational by default; `runtime` and `startup` say `not collected: <reason>`
  in the hunk summary and fail; `bus` says `not collected: no bus configured` in
  the run log only. Each is loud in its own way; unifying the wording touches
  test-held strings and was not done.

## Pending validation

Nothing below could be done without Docker, a registry, network or the real
tools. Each must happen before the harness gates on the artefact concerned.

- [ ] **First noise A/A** on the production tag with Docker: must be clean (0 hunks)
      with all nineteen artefacts collected. Expect trouble first from `startup`
      (compose healthchecks tick every 2 s) and `runtime`.
- [ ] **Mutants on the Quay tag: 10 of 10** caught and attributed (weekly workflow,
      or `pnpm harness mutants --base <tag>`). In particular `base-swap` on
      `ubuntu:24.04` (alpine cannot receive the production filesystem) and `added-package` with syft.
- [ ] **syft output shape** (SPDX JSON as `syft docker:{image} -o spdx-json`
      prints it), and the SBOM cosign attestation the monorepo actually attaches
      (`cosign verify-attestation --type spdxjson`, same identity and issuer).
- [ ] **grype output shape**, and a pinned database: `vulns` is "not collected"
      (informational) until a runner has grype and `HARNESS_VULN_DB_DIR` set.
      No workflow installs grype or provisions a database yet; only
      `weekly-mutants.yml` installs syft.
- [ ] **Posture probe assumptions**: `node` on the PATH inside every app image,
      `/proc/self/mountinfo` layout, compose health status format, kind pod spec
      fields. Also the compose service and kind pod names the collectors address.
- [ ] **Arbitrary-UID probe**: the posture probe runs as the image's own USER, not
      the random UID OpenShift's restricted-v2 assigns ([../modes.md](../modes.md)).
      Not built.
- [ ] **Workflow output and artifact names**: the `noise` branch layout,
      `noise-status.json` and the `noise-history.json` written by the nightly, the
      release-dispatch outputs in `docs/monorepo/release-dispatch.yml`, the
      `override-record` and `publish` jobs. Checked against this repository's tests
      only, never by a real dispatch.
- [ ] **Image cache**: save, restore and the DEGRADED path with a real registry
      outage (or a blocked network on a test run).
- [ ] **A real `--mode release` end to end** with SBOM attestation, override and
      claim hygiene in the PR comment.

## Owner decisions still open

- **Mann-Whitney `normalCdf`** in `src/compare/engines.ts` is wrong (the z passed
  in should be divided by the square root of 2). Not fixed here; a separate change
  owns it. It affects `timing`, load and, through the shared function, `startup`
  in `src/compare/runtime.ts`. A/A results on those engines before the fix are not
  evidence either way.
- **`ENGINE_PATHS`** (`src/ci/engine-change.ts`) does not include
  `src/collectors/**`, and now also not `src/runtime/**`, `src/image-static/**`,
  `src/persistence/**`, `src/migration/**`, `src/bus/**`: a PR that changes what
  is collected, without touching an engine, needs neither a version bump nor the
  mutants. Not added; owner decision.
- **The `time` app** is missing from `APPS` in `src/image-ref.ts` and from
  `compose.harness.yaml`. The harness therefore knows only `reader`, `catalogue`
  and `live`, and none of the artefacts above is collected for `time`.
- **Monorepo digest fields in the dispatch contract**: whether the monorepo's
  `repository_dispatch` payload should carry the image digests it published
  (see [../contract.md](../contract.md#repository_dispatch) and
  `docs/monorepo/release-dispatch.yml`).
- **Footer version mask** `[data-tutors-build=version]`: whether to add a mask
  for the app footer's build version in `normalise/masks.yaml`. It is a mask, so
  it lands in its own PR (`src/ci/mask-change.ts`).
- **Smoke A/A and startup restarts** (above): make `--startup-restarts` stable and
  pass `0` in the `ci.yml` smoke run, or leave it sampling.
- **`HARNESS_REQUIRE_STATIC` in release**: whether a release must fail when an
  SBOM diff cannot be produced (the flag exists; no workflow sets it).
- **Whether `runtime`/`startup` "not collected" should stay failing** while the
  static artefacts' equivalent is informational.

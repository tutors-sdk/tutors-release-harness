# Harness 1.21.0 (contract 1.21.0)

Engine levels: informing before blocking. Until now a new engine gated from its first run, so
there was no way to watch a check for a few weeks before it could stop a release. Every engine
now has a level, **blocking** or **informing**, and an informing engine's findings are reported,
never gated. The first step of the "Policy" release, and the mechanism that makes the rest of it
safe to add. The contract changelog entry is in [../contract.md](../contract.md#changes). A
**minor** for the new `report.json` and `readiness.json` fields.

## What is new

- **Every engine has a level** (`ENGINE_LEVELS` in `src/compare/levels.ts`), named by its
  artefact: `blocking`, as every engine has always been, or `informing`, with an optional
  `blockingFrom` date (UTC, `YYYY-MM-DD`) from which it blocks with no harness release in between.
  An engine left out of the table is blocking.
- **An informing result never gates.** A hunk an informing engine would have failed is written as
  `severity: info` with `level: informing` (and its `blockingFrom`), so it is not in
  `compare.unclaimed`, no verdict, Gate or exit code reads it, and the A/A does not count it. It
  stays claimable: a claim that names it is recorded as matching it and is not stale.
- **Labelled wherever it shows.** `report.html` and `report.md` list informing results under
  **Informing**, "reported, never gates", with every engine's level ("Every engine is blocking
  (19 of 19)" today), and a row of the differences table says "informing" where it would have
  said "unclaimed". `report.json` records every engine's level in `levels`. The readiness page
  shows each forecast's unclaimed informing results beside its Gate ("2 informing") and in a
  tile of their own on the latest forecast; `readiness.json`'s forecast gains `informing`.

## Nothing is decided differently

Every engine is blocking, so a run that passed on 1.20.5 passes on 1.21.0 and one that failed
fails, with the same hunks. The next steps of the Policy release add checks that ship informing.

## Upgrading

Nothing to do. A reader of `report.json` that counts failing hunks by `severity` keeps counting
what gates. A new engine or check should ship informing (TESTING.md, "Rules for a new engine").

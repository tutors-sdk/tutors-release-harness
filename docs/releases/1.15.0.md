# Harness 1.15.0 (contract 1.15.0)

Fixes on b are decisions, not failures. An accessibility violation that b no longer has, or a
console error that is gone, never gated a release. But the harness still treated it as a gap: the
glance called it "unclaimed", and the claim written for it (the four axe claims of mono-repo
#364, Rules 0216, 0051 and 0036) read as stale, so the Gate said to remove it. 1.15.0 lets a claim
decide a fix, and shows decisions in orange, beside the traffic lights and never on them. The
contract changelog entry is in [../contract.md](../contract.md#changes). It is a **minor** release:
no verdict, exit code, command or flag changes.

## What is new

- **A claim decides a fix.** The matcher records a claim beside the info hunk it names, so the
  claim is used, not stale. An info hunk still never gates.
- **The claim is the switch.** The glance's "fixed on b" item reads "undecided" until a claim
  names the fix, then switches off. It stays when the same page has new failures of the same kind
  ("fixed, or only changed?").
- **The A3 shows decisions in orange.** An orange strip under the final scoring gives the share
  decided, per artefact (accessibility, console errors). The root cause column gains a "Decisions
  on b" table: each page, what was fixed, decided or not, and the claim that says why. A report
  written before 1.15.0 reads correctly too: a claim it called stale but that names a fix counts as
  deciding it.
- **Claim guidance**: `claims/README.md`, "A fix on b is a decision".

## Upgrading

Nothing to do. Claims written for a fix that 1.14.0 called stale now count; remove none of them.

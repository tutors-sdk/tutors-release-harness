# Harness 1.35.1 (contract 1.35.0)

Docs that had drifted from the code, and the code after capture made as pure as the guide says it is
(issue #102). A harness-only **patch**: no input, output field, verdict, exit code, claims key, flag,
workflow or mask changes, so the contract stays at 1.35.0. It touches engine paths (`src/stack.ts`,
`src/normalise/masks.ts`, `src/claims/schema.ts`, `src/slo/schema.ts`), so the version moves and the
mutants re-run.

## What changed

- **`src/root.ts`** holds `ROOT`, the checkout root, as a leaf module. `src/stack.ts` re-exports it.
  The masks, claims and SLO loaders import it from there instead of from `src/stack.ts`, so nothing
  after capture loads the stack's Docker plumbing. `tests/purity.test.ts` walks the import graph from
  the compare engines, masks, claims, SLO, report and gate code and fails if any of it reaches the
  stacks, the images, the collectors or `node:child_process` (`src/version.ts`, which reads the
  harness's own git sha to stamp a report, is the one stated exception).
- **Sixteen mutants**, not thirteen, in decision 14, chapter 5 of the user guide and chapter 9.
- **`mutants/README.md`** says which test kills each mutant (the self-test, by name) and what the unit
  tests hold for each; `tests/mutant-build.test.ts` fails when a mutant is missing from that table.
- **The architecture docs** say they are a snapshot drawn at harness 1.4.1, and that a path marked
  "monorepo" is in `tutors-sdk/tutors-mono-repo` (`scripts/promote-image.ts`, `deploy/k8s/`,
  `tests/bdd/features` and the rest).
- **`scoreboard/mutants.jsonl`** is said to live on the `scoreboard` branch wherever the docs name it.
- **`docs/masks.md`**, which never existed, is dropped from the mask PR guard's allowed paths
  (`src/ci/mask-change.ts`) and from the guide.
- The user guide's version line names 1.35.1.

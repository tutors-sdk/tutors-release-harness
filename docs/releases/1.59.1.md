# Harness 1.59.1 (contract 1.59.0)

A migration claim covers its migration in the migration rehearsal, and is never stale in the release run. This is a **patch**: no shape or exit code changes.

## Why

The 28 Oct forecast (`sha-d350404` beside 17.0.0, harness 1.59.0) failed twice over one claim. Main's `release/claims.yaml` claims the removed policy `app_errors:anon_select_app_errors` (artefact `migration`). The release run, which never sees a migration, reported the claim as stale ("8 claim(s) matched nothing"), and the migration rehearsal, run without any claims, failed on that very policy ("1 expand/contract or rollback violation(s)").

## What changed

- `src/run.ts` `judgedHere`: a claim is stale only in a run that could have matched it. In the migration rehearsal only `migration` claims can be stale, in the upgrade rehearsal only `upgrade` claims, and in every other run neither.
- `main-preview.yml`, `release.yml` and `harness local gate`: the migration rehearsal reads the same claims as the release run (`--claims`), with main's Rules (`--rules`) where a claim names one.

# Harness 1.49.1 (contract 1.49.1)

Two fixes found by the 20 Oct forecast (`sha-a31e5ef` beside 17.0.0), whose Gate failed on 23 differences no claim covered and no PR declared. A **patch**.

## Why

- **4 `startup` differences were the harness's clock, not the apps.** Every app read ready ~3 s slower on b (median ~2.27 s to ~5.31 s) while the first healthy `/` did not move (~300 ms). Mono-repo #501 gave the image a `HEALTHCHECK --start-period=10s`. Compose overrides the image's interval with its own 2 s, but Docker keeps the image's start period when compose names none, and inside a start period it probes at the start interval, 5 s by default. So the first probe that could say healthy came at 5 s.
- **18 `sbom` differences were blamed on "one of #518, #519, #491".** `@supabase/*` and its 8 dependencies left the time image and arrived in the reader's. #518 alone changed `apps/reader/package.json` and #519 alone `apps/time/package.json`, but an app's own manifest only counted as an indirect match, the same as the root `package.json` #491 touched.

## What changed

- `compose.harness.yaml`: the apps' healthcheck sets `start_period: 2s` and `start_interval: 2s` (compose takes the second only beside the first), so `startup` `*/ready` keeps the harness's 2 s cadence whatever the image declares.
- `src/changes/attribute.ts`: for `sbom` and `vulns`, `apps/<app>/package.json` of the cause's app is a direct path beside the Dockerfiles. On the 20 Oct forecast this names #518 for the reader's 9 added packages and #519 for time's 9 removed ones.

No verdict, Gate or exit code rule moves.

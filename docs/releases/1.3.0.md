# Harness 1.3.0 (contract 1.3.0)

`main` is at 1.1.0; this is its next release. 1.2.0 was built but never released
on its own, so 1.3.0 carries everything 1.2.0 was going to carry, plus the
local-first work, the contract additions that followed, the `time` app and the
statistics fixes. There is one version: the harness version and the contract
version are both `1.3.0` everywhere, and the full contract changelog (with the
1.2.0 entry kept as the history of the first part) is in
[../contract.md](../contract.md#changes).

Everything in the contract is additive for a consumer written against 1.1.0,
with the exceptions listed under
[Behaviour that changes](#behaviour-that-changes-without-a-flag-or-field). This
release integrates: R0/R1 close-out, R3 noise burn-down enablers, R5 static image
artefacts, R5 runtime artefacts, R7 persistence abstraction (all of 1.2.0);
local-first (`harness doctor`, the local noise store, guards and wrappers);
contract 1.3.0 (digests, rules, release records, stable commands, checkout
names); the `time` app; the Mann-Whitney fix; a complete `ENGINE_PATHS`;
A/A determinism fixes; the pinned vulnerability database (`harness vuln-db`, grype in
the workflows); one "NOT COLLECTED" convention; `harness prune` and `harness local
smoke`; clean exit-2 errors and `--help`; and what a production post-deploy run showed
(canonical headers, symmetric origins, redacted secrets).

Nothing in it has been run against Docker, a registry or the real tools as a
whole. The unit tests drive every collector through an injected runner. What
that cannot prove is listed under [Pending validation](#pending-validation).

## What is new

- **Nineteen artefacts** (six new since 1.1.0): `bus`, `image-manifest`, `sbom`,
  `vulns`, `runtime`, `startup`.
  - `image-manifest`, `sbom`, `vulns`: read from the images before the stacks
    start. SBOM from the cosign SPDX attestation of a pulled image, or generated
    locally (`HARNESS_SBOM_SOURCE=generate`); vulnerabilities from a pluggable
    scanner (grype by default) over that SBOM with a pinned database.
    [../images.md](../images.md).
  - `runtime`, `startup`: container posture (declared and measured from inside)
    and time to healthy over N restarts. [../modes.md](../modes.md).
  - `bus`: topics published during a journey, when a bus is configured. Groundwork
    only until a bus exists. [../bus.md](../bus.md).
- **Ten mutants** (eight edge faults, two image-level): the two new ones are
  `base-swap` (expects `image-manifest`) and `added-package` (expects `sbom`).
- **Four apps.** The `time` app joins `APPS` (`reader`, `catalogue`, `live`,
  `time`). It is in both compose sides (host ports `3104` and `3204`), the kind
  manifests and `kind-config.yaml` (NodePorts `30103` and `30203` on host `4103`
  and `4203`), image resolution and verification, the static image artefacts,
  `runtime`, `startup`, `metrics` and `logs`, the report tables and
  `scripts/build-images.sh`. It is client-rendered and no journey drives it, so it
  has no `dom`, `network`, `headers`, `axe`, `screenshot` or `timing` artefact;
  `StackUrls.time` exists for origin normalisation and the collectors. No
  existing journey step targets it. A `reader=...,catalogue=...,live=...` spec
  written for 1.2 keeps working: `time` takes the reader's tag.
- **Local-first.** `harness doctor` (what this machine lacks, and how to install
  it), `harness noise record|status|history`, `harness guard masks|engine|all`,
  `harness override list`, and the maintainer wrappers `harness local
  nightly|gate|mutants|watch|smoke`, planned from the same commands the workflows run
  (held by `tests/local-parity.test.ts`). A local state directory `HARNESS_HOME`
  holds the noise store, the override log, the run lock and the release records.
  Windows fixes (`HARNESS_BASH` (not contract), native temp paths in the shell scripts). The
  workflows are thin: CI calls the same commands. [../local.md](../local.md).
- **Digests, release records and the deployment check.** The dispatch may carry
  `production_digests` and `candidate_digests` (`--a-digests`, `--b-digests`):
  pinned images are pulled and verified by digest, a moved tag is refused (exit
  `2`), and a pinned image is never built from source. Release mode writes a
  release record (`release-record.schema.json`); the new `publish-record` job of
  `release.yml` publishes it to the `release-records` branch; post-deploy mode
  compares what was deployed with it and warns on a difference.
- **`rule` on claims.** A claim may name a Rule (`rule: "0031"`), checked against
  `rules.json` (`--rules`, `rules_url`, `rules.schema.json`).
- **Checkout names.** The compose project and kind cluster name derive from the
  checkout path (`tutors-harness-<8 hex>`), so worktrees never share a stack;
  `HARNESS_PROJECT`, `HARNESS_COMPOSE_PROJECT`, `HARNESS_KIND_CLUSTER` override.
- **A pinned vulnerability database.** `harness vuln-db update|status` fetches and reads
  one grype database in one directory (`HARNESS_VULN_DB_DIR`, else
  `<HARNESS_HOME>/vuln-db`); every scan runs with updates off against it, so both sides
  of a comparison see the same advisories. The nightly, the release job and the weekly
  mutants install grype at a pinned version, restore the database from a per-day cache
  and print its status first; `harness doctor` checks grype's version, the directory
  and the database's age (`HARNESS_VULN_DB_MAX_AGE_DAYS`, default 5).
  [../images.md](../images.md#the-vulnerability-database).
- **One "NOT COLLECTED" convention**, see [below](#not-collected-one-convention).
- **Housekeeping commands.** `harness prune` frees `out/` and the image cache (a dry
  run unless `--yes`; never touches `HARNESS_HOME` state, the newest release run that
  did not FAIL, anything from the last six hours, or anything a running task holds),
  and `harness local smoke` (also `pnpm smoke`) is the two-stacks smoke that `ci.yml`
  now calls: both stacks boot, one journey runs A/A, the expanding migration passes and
  the contracting one is rejected. [../local.md](../local.md).
- **Cleaner exit 2.** `--help`, `-h` and `help` print usage and exit 0; a claims or
  rules file that cannot be used is a multi-line message, not a stack trace; a run that
  cannot judge no longer leaves an empty output directory; `post-deploy.yml` opens the
  `rollback` issue on exit 1 only.
- **Post-deploy against an external side** (what a production run showed):
  `content-type` and `cache-control` are compared in one canonical form on both sides;
  header masks may carry a pattern (the CDN-only masks themselves land in a masks-only
  PR); production's own URLs read as `{{origin}}` on both sides; secret-shaped values
  (`apikey=`, `Authorization`, JWTs, `sb_publishable_`/`sb_secret_` keys) are redacted
  before a capture or a report holds them; a local WARN says `decide whether to roll back`
  and never promises an issue (`HARNESS_ROLLBACK_ISSUE`); `harness local watch` stamps its
  lines. Contract: [../contract.md](../contract.md#changes).
- **Noise burn-down enablers (R3)**: nightly A/A on pulled and verified images
  with the k6 load, an image cache as the Quay-outage fallback (`cached`
  provenance, DEGRADED status), the status published to the `noise` branch,
  a clean-streak ratchet, a "masks land in their own PR" CI guard (warns past
  40 masks), claim hygiene, recorded overrides of a FAIL, and the fix for
  `post-deploy.yml`, which was not valid YAML. [../noise-burndown.md](../noise-burndown.md).
- **Persistence seams (R7)**: a recorder seam under the persistence collector, a
  ledger comparison (`src/compare/ledger.ts`), a migration backend seam, a clock
  probe. Behaviour on the current Supabase stack is unchanged.
  [../harness-now.md](../harness-now.md).
- **R0/R1 close-out**: a report banner (markdown and HTML) when a side is not the
  published, verified image, now also for `cached`; reference copies of the
  monorepo's workflows under `docs/monorepo/`, held by `tests/monorepo-docs.test.ts`.

### Not collected: one convention

An artefact the harness cannot collect must never read as "no difference". Four
collectors said so in four ways:

| Artefact | Text | Hunk | Severity |
| --- | --- | --- | --- |
| `image-manifest`, `sbom`, `vulns` | `NOT COLLECTED: <kind> of <apps> on side b: <reason>. It was not compared.` (reasons); `<app>: sbom NOT COLLECTED on side b, so it was not compared` (hunk) | `<app>/not-collected` | informational, failing with `HARNESS_REQUIRE_STATIC=1` |
| `runtime`, `startup` | `<app>: container posture not collected: <reason> (side b)` | `<app>/not-collected`, `runtime/not-collected`, `startup/not-collected` | failing, informational when switched off |
| `bus` | `bus traffic not collected: no bus configured` | none | none: run log and `capture.json` only |

One helper, `src/not-collected.ts`:

- **Text**: `NOT COLLECTED: <what>[ of <subject>][ on side a|b, or on both sides]: <reason>`,
  the same in `reasons`, in a hunk `summary` and in the run log.
- **Hunk**: the artefact's own `artefact`, and `scope` `<subject>/not-collected`,
  where the subject is an app or, when the whole artefact is missing, the artefact
  (`runtime/not-collected`). These scopes are exactly what they were, so no existing
  claim (`artefact: runtime, scope: "*/not-collected"`) stops matching.
- **Severity, one rule**: informational, unless the artefact is *required*, and then
  failing; always informational when an operator switched it off (`--no-runtime`,
  `--startup-restarts 0`).
- **Required**: `runtime` and `startup` by default; anything named in the new
  `HARNESS_REQUIRE_ARTEFACTS=<list>` (artefact names, `static` for the three image
  artefacts, `all`). `HARNESS_REQUIRE_STATIC=1` stays as an alias for `static`; the two
  add up, an unknown name is an error (exit 2), and the list only ever adds, so no
  setting can loosen a gate. `harness doctor` and `harness vuln-db status` read the same
  requirement for grype.

Nothing changes in a verdict, an exit code, a hunk's `artefact`, `scope`, `path` or
`severity`, or a claim, on any run that does not set the new variable. Decided by the
owner for this release:

- **The convention ships in 1.3.0**, with a bullet under 1.3.0 in
  [contract.md](../contract.md#changes).
- **`runtime` and `startup` stay failing when not collected, by default.** Both collectors
  run `docker`/`kubectl` against stacks the harness started itself, so an empty one is a
  fault (no such container, a probe that crashed), not a missing tool, and a nightly A/A
  whose ratchet is "0 artefacts not collected" (TESTING.md) would stop meaning anything if
  it went quiet. They are in the default required set (`DEFAULT_REQUIRED` in
  `src/not-collected.ts`).
- **`bus` stays informational and quiet until a bus exists.** It has the same text in its
  run-log line, and a `capture.json` `bus.reason` of `no bus configured` / `external
  deployment` (`capture.json` is not part of the contract), but adds **no hunk** by
  default, because [../bus.md](../bus.md) promises that a run with no bus is byte-for-byte
  what it was. With `HARNESS_REQUIRE_ARTEFACTS=bus` a side with no bus is a failing
  `bus/not-collected` hunk (never asked of a live deployment).

The **text** changed (a `summary`, a `reasons` line, the run log; the contract only
promises `artefact`, `scope`, `path` and `severity` of a hunk): a tool that matches a
summary must match the new form. The static artefacts' `reasons` line lost its trailing
"It was not compared."; the runtime and startup summaries say `on side b` inside the text
instead of a trailing `(side b)`. New: `HARNESS_REQUIRE_ARTEFACTS`, and per-artefact
requirement (`=sbom` fails only the SBOM gap, where `HARNESS_REQUIRE_STATIC=1` was all
three). The change is in `src/compare/**` and `src/not-collected.ts`, engine paths: this
release's version bump covers it.

### The Mann-Whitney p-value was wrong

`normalCdf` passed z to the erf approximation where the normal CDF needs
z / sqrt 2, so every p-value on `timing` (page TTFB, journey duration), `load`
and `startup` was too small: a perfectly separated 5 v 5 reported p = 0.0004
(correct 0.0122), 3 v 3 reported 0.014 (correct 0.081). The test now lives in
`src/compare/stats.ts`, dependency-free, on an erfc that keeps its precision in
the tail, with `tests/stats.test.ts` holding hand-derived values.

**Reports and A/A history from 1.2.0 and earlier are not evidence about these
engines**, either way: a noise count taken with the wrong p says nothing about
the noise floor of the right one.

What each configured sample count can reach, for n v n perfectly separated (the
smallest p the test can produce; normal approximation with continuity
correction, which is what the engines use; the exact permutation p is in the last
row for comparison):

| n a side | 2 | 3 | 4 | 5 | 6 | 8 |
| --- | --- | --- | --- | --- | --- | --- |
| best possible p | 0.245 | 0.081 | 0.030 | 0.012 | 0.0051 | 0.0009 |
| reaches alpha 0.05 | no | no | yes | yes | yes | yes |
| exact p (2 / C(2n, n)) | 0.333 | 0.100 | 0.029 | 0.008 | 0.002 | 0.0002 |

With one overlapping pair, 4 v 4 is p = 0.061 (no longer significant) and 5 v 5
is 0.022 (still is). So **three runs cannot reach alpha 0.05 and four is the
least that can**; five is the least that survives one overlap.

Audit of everything that used the function:

| Consumer | Configured samples | Verdict |
| --- | --- | --- |
| page TTFB, journey duration (`timing`) | `--runs` (one visit per page per run) | 3 could never reach alpha; now says so, as information, and the nightly A/A and `release.yml` default to 5 |
| `load` (k6) | hundreds to 2000 a side | reaches alpha trivially; also says so if k6 left too few |
| `startup` | 5 restarts (default) | reaches alpha (0.012); 3 cannot, and already said so |
| `normalise/masks.yaml` `timing` | `minRuns 3`, `alpha 0.05`, `minEffect 0.2` | left as is: a threshold change is a mask PR, and the engine now derives the real floor from alpha; the comment says so |
| `mutants/mutants.yaml` `slow-ssr` | `runs: 3` | could only be caught because of the bug; now `runs: 5` |
| `release.yml`, `nightly-noise.yml`, `harness local` | 3 | now 5 (`release-candidate` `runs` default is contract-visible, see the contract's 1.3.0 entry) |

Cost: each run is one more pass of every selected journey on both sides. Measured
on a laptop (fixture and auth sets, compose): about 43 s per extra run, so 3 to
5 runs is about 1.5 minutes more per release or nightly run, and `slow-ssr` takes
about 4.3 minutes against 1.4 for a one-run mutant.

### `ENGINE_PATHS` is complete, and cannot rot

`src/ci/engine-change.ts` now treats every directory and file that can change what
a report says as engine code: the collectors, runtime, static image artefacts,
persistence, migration and bus directories, the clock probe, the claim matcher,
`run`, the modes, `noise`, `stack`, the substrates, image resolution and digests,
the release record, the stack files, fixtures, scripts, `traffic/**` (journeys
and k6), the mutant runner and builder, and `pnpm-lock.yaml`. Everything else
directly under `src/` or at the root is listed as non-engine with a reason
(`src/local` and `src/project.ts` among them), and `tests/engine-change.test.ts`
fails when a new one is in neither list. [../../TESTING.md](../../TESTING.md).

### Behaviour that changes without a flag or field

- The new artefacts are collected on every run. A `runtime` or `startup` artefact
  that could not be collected is a failing hunk; a static image artefact that
  could not be collected is informational unless `HARNESS_REQUIRE_ARTEFACTS` names it (or
  `HARNESS_REQUIRE_STATIC=1`, which the nightly and the release job set).
  Compare with the same tag under 1.1.0 and you will see new hunks, not new
  fields; reports of different harness versions are not comparable (contract,
  Compatibility).
- `release-candidate` `runs` defaults to `5`, not `3`, and the nightly A/A runs
  five. A dispatch that passes `runs` is unaffected.
- A `rule` key in a claim was ignored before and is now checked.
- A missing `--noise` no longer means "no status" on a machine that has a local
  noise store (the workflows pass `--noise` and are unaffected).
- The default compose project and kind cluster name changed (see the decisions).
- Canonical header forms, symmetric origins on an external side and redaction change
  what hunks say, and can remove hunks an earlier build showed; a report is comparable
  only with one of the same harness version.
- A base tag must now exist for `time` as well (`harness images ensure` fails,
  loudly, if the registry has none).

## Decisions taken

Recorded by the owner for this release:

- **`runs` defaults to 5** in `release-candidate`, the nightly A/A, `harness local`
  and the `slow-ssr` mutant. Four is the least that can reach alpha 0.05; five is
  the least that survives one overlapping pair.
- **Kind clusters created before 1.3.0 must be recreated.** They never published
  the time ports, and the cluster name is now derived from the checkout path
  (`tutors-harness-<8 hex>`). A cluster called `tutors-harness` is never adopted
  or deleted: `harness kind` refuses that name, and `harness doctor` reports it as
  a legacy cluster. A compose stack under the old project name is reported the
  same way, not touched.
- **`HARNESS_REQUIRE_STATIC=1` in the nightly and the release job, not in the weekly
  mutants**: the nightly is the canary for a scanner or SBOM that silently stopped, a
  release must not pass without the SBOM and vulnerability diff, and the mutants judge the
  harness, not an image ([../images.md](../images.md#the-vulnerability-database)).
- **The post-deploy CDN masks are a masks-only PR**, after this one merges: what only exists
  because production sits behind Netlify needs the header-mask `pattern` mechanism that is
  in this release, and `masks.yaml` does not change here beyond comments.
- **`time=` is optional** in `--a`/`--b` and in `--production`; left out it takes
  the reader's tag, so a spec written for 1.2 keeps working.
- **One 1.3.0.** There is no 1.2.0 or 1.2.1 release: the contract keeps the 1.2.0
  entry as history and folds the statistics fixes and the `time` app into 1.3.0.

Taken while integrating (from 1.2.0):

- **Startup restarts are off in two places**: `harness mutants` (and so the
  weekly workflow) and `upgrade` mode. `harness mutants` also forces
  `HARNESS_SBOM_SOURCE=generate`, because a mutant is a local build with no
  attestation; both settings are applied together and independently. The per-PR
  smoke A/A in `ci.yml` was left as it is: it now restarts every app five times
  per side, and `--startup-restarts` is a non-stable flag, which
  `tests/contract.test.ts` forbids workflows from using. Either make the flag
  stable (a minor addition) and pass `0` there, or accept the cost and the
  flake risk; see the open decisions.
- **`startup:` block in `normalise/masks.yaml` is commented out.** An uncommented
  block is a threshold change, and `src/ci/mask-change.ts` would fail this PR,
  which changes much else, for it. The default (250) lives in
  `src/normalise/masks.ts`, so behaviour is identical. Tuning it is a
  masks-only PR.
- **The provenance banner covers `cached`** as it does `built-from-ref` and
  `pulled-unverified` (the R3 branch had a dead copy of that list in the HTML
  provenance table; the shared `loudProvenance` is the one place now).
- **Masks land in their own PR.** The `persistence-stub-requests` mask found by
  the A/A fixes below is not in this release's PR: it is in the masks-only PR
  (`chore/mask-footer-version`), which goes to `main` first, and `main` is then
  merged into this branch. Until then an A/A on this branch shows the
  signed-in reader's timer-driven calls to its persistence stub (4x on a, 3x on b).

## Fixes found by running it

Running the mutants self-test against the Quay `main` images, which CI aborted
on ("A/A is not clean (13 diff(s))"), found these defects:

- console errors naming the side's own persistence stub over `ws://` were never
  normalised (`stripOrigins` knew only the `http` form);
- a JSON response whose body the browser dropped was recorded like a response
  with no shape, so one side reading it and the other not was a schema change
  (now `unread`, and not compared);
- an unbounded `response.text()` hung the run for as long as anyone waited on the
  `anon-write` mutant (a page that fires a request and never reads the reply);
- `base-swap` could not be built: `COPY --from=production / /` over `alpine`
  fails in BuildKit because the node image's `/bin` is a symlink; it now swaps
  onto `ubuntu:24.04`;
- the signed-in reader's timer-driven calls to its persistence stub showed up 4x
  on a and 3x on b in an A/A: a mask, in the masks-only PR (see above).

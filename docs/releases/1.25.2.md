## The usage audit

Every `pnpm harness …` line in the README, the user guide, `docs/local.md` and `TESTING.md` was
checked. Each one's flags were compared with `harness help <command>`. Every command that needs no
Docker was run from a clean checkout: version, journeys, doctor, noise, vuln-db, prune, guard,
confidence, glance, why, scoreboard, changes, release `--dry-run`, every `local … --dry-run`,
`compare` on a fixture, the user guide's chapter 9 example verbatim, and chapter 3's worked example
against the kept 2026-09-27 forecast. These were fixed:

- `harness compare` takes `--masks` (chapters 5 and 8 use it); its usage line now says so, and
  the README's usage line also gains `--rules`.
- `pnpm stack:down` needs `--a` and `--b`, the same refs as the run that kept the stack.
- `TESTING.md`'s upgrade rehearsal with the `route-500` mutant named one image with no app. That
  makes all four apps `tutors/<app>:latest`, so the mutant was not in the run. It now spells out
  `reader=…` beside the other three.
- Chapter 3 says what its worked example needs to give its numbers: the monorepo's full history,
  and a GitHub token for review coverage. Without the token, Change risk shows 11 deductions, not 60.
- The `harness version` example shows `X.Y.Z`, not 1.13.0.

# Harness 1.59.0 (contract 1.59.0)

The gate reads the code, not the title. A difference is explained when the PR whose code made it can be named, whatever its CHANGELOG hint says; a hint that leaves out what moved is a warning on the A3. This is a **minor** release: what counts toward PASS, explained widens, and `a3.json` gains `gap.mismatches`.

## Why

After harness 1.58.0 the 28 Oct forecast (`sha-d350404` beside 17.0.0, [run 40659406748](https://github.com/tutors-sdk/tutors-release-harness/actions/runs/40659406748)) still failed with 332 unclaimed differences, every one attributed to a PR, most to mono-repo #327. #327's title hint said `(logs, sbom)`, so its network, console, dom, focus and persistence differences counted as owed even though the harness had already named #327 as the PR whose files made them. Leigh (28 Oct): "I feel this is semantics and forces perfection in naming conventions. Are we looking at the code change? Vs the title?" and "have a warning section on the A3 that says title / PR description mismatches so we have an alert. To me functionally pinning it to a code change is exactly what we want".

## What changed

- `src/changes/explain.ts`: a contributed row one PR leads (`leads()`: its files match more than any other PR merged that night) is `pinned` and explained. `declaredPass` passes when every unclaimed difference is declared or pinned and nothing is unexplained; a group no PR leads still fails.
- Orphans (no merge, too many PRs, before the record, first measured) are adopted by the one PR that is pinned or declared for the same kind of difference in the same run (`adopted`). Two PRs with the same kind leave it unexplained.
- `src/changes/attribute.ts` `byRoute`: a new request (`network`) is pinned on the one PR whose files hold the SvelteKit endpoint it reaches (`POST /api/courses/visit` → `apps/<app>/src/routes/api/courses/visit/+server.ts`; `[param]`, `[...rest]`, `[[optional]]` and `(group)` segments understood). It also breaks a tie in a group merged the same night.
- `hintMismatches` / `mismatchWords`: each pinned PR whose hint leaves out an artefact its code moved, and how many differences. The A3's gap section shows them under **Warning: Hint mismatches** (`id="hint-mismatches"`), and the PASS, explained note ends with the same warning.
- `gateWhy`: "FAIL only because N differences are not claimed yet, and each is pinned on the PR that made it (…)" when that is the only reason.

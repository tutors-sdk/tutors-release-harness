# Harness 1.48.0 (contract 1.48.0)

The whiteboard drawn on alone. Rule 0592 has the enrolled student open the Rule journeys' course's whiteboard, press
Edit, draw one stroke and wait for the scene to save. A **minor**: new pages, and one more third-party host.

## Why

The whiteboard is the one learning object whose cost is mostly Realtime and writes: the editor saves the scene to
`whiteboard_scenes` and, when others are on the board, broadcasts scene changes and cursors. No journey opened it, so a
build that saved on every pointer move, or broadcast to an empty room, moved no artefact the harness compared.

## What changed

- **Rule 0592** (exercises 0275, 0276; the monorepo's realtime-usage and course-tools features): as the enrolled
  student, alone, open Topic 1 and Whiteboard 1, press Edit, draw one freehand stroke, and wait for
  `Drawing changes saved`. One page: `reader:rule-0592-stroke-saved`. The ledger holds the scene's save, and the
  realtime artefact what the editor sent with no one else on the board.
- **The Rule journeys' course** holds an empty whiteboard, `whiteboard-01` in Topic 1, rebuilt from the monorepo's
  main (`83d4ccf`).
- **`esm.sh`** is answered from the third-party record, like the fonts, icons and KaTeX: the whiteboard's editor loads
  Excalidraw and React from it, and both sides now draw with the same bytes.
- New step: `the student draws a stroke on the whiteboard "<title>"`. `the student opens the whiteboard "<title>"` is
  the card step that opens talks, notes, notebooks and quizzes.

## Proved

Run locally on images built from tutors-mono-repo main (`83d4ccf`): `--journey rule-0592-whiteboard`, an A/A run with
`--runs 3`, is clean.

## What a consumer does

Nothing.

# Harness 1.48.3 (contract 1.48.3)

The A3 counts only the line stops about the monorepo. A **patch**.

## Why

The A3's "Why the line stops, every red run" mixed the harness's own problems in with the monorepo's: nights the A/A
was degraded or noisy, a run that built an image because it could not pull it, and post-deploy runs that failed before
they judged production (no recorded release, a workflow that could not start). Leigh, 18 Oct 2026: CI runs on the A3
should be about the monorepo only, and harness issues must not pollute it.

## What changed

- **Why the line stops** (now "every red run about the monorepo") counts the Main to RC forecasts and release
  candidates, without the stops the harness made about itself (`HARNESS_STOPS` in `src/a3/model.ts`), and the
  post-deploy runs that judged production and found it different. The Nightly A/A's stops are left out; the A/A keeps
  its own question, Q5 ("Can the A/A be trusted").
- **Post-deploy** (the score's red count, the value stream's andon and first-pass yield): a run that failed at any step
  but "Post-deploy mode" is left out. It says nothing about production, red or green.

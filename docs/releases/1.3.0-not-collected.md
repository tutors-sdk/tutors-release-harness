# Not collected: one convention (for 1.3.0, needs a contract decision)

Status: implemented on `chore/harness-housekeeping`; **not** part of a contract
bump. The contract is `1.3.0` and stays `1.3.0`; this note is what a maintainer
needs to decide whether the change rides with 1.3.0, waits for 1.3.1, or is
narrowed. It answers the last open question of
[1.2.0's release notes](1.2.0.md): whether `runtime` and `startup` "not
collected" should stay failing while the static artefacts' equivalent is
informational.

## The problem

An artefact the harness cannot collect must never read as "no difference". Four
collectors said so in four ways:

| Artefact | Text | Hunk | Severity |
| --- | --- | --- | --- |
| `image-manifest`, `sbom`, `vulns` | `NOT COLLECTED: <kind> of <apps> on side b: <reason>. It was not compared.` (reasons); `<app>: sbom NOT COLLECTED on side b, so it was not compared` (hunk) | `<app>/not-collected` | informational, failing with `HARNESS_REQUIRE_STATIC=1` |
| `runtime`, `startup` | `<app>: container posture not collected: <reason> (side b)` | `<app>/not-collected`, `runtime/not-collected`, `startup/not-collected` | failing, informational when switched off |
| `bus` | `bus traffic not collected: no bus configured` | none | none: run log and `capture.json` only |

## The convention

One helper, `src/not-collected.ts`:

- **Text**: `NOT COLLECTED: <what>[ of <subject>][ on side a|b, or on both sides]: <reason>`,
  the same in `reasons`, in a hunk `summary` and in the run log.
- **Hunk**: the artefact's own `artefact`, and `scope` `<subject>/not-collected`,
  where the subject is an app or, when the whole artefact is missing, the
  artefact (`runtime/not-collected`). These scopes are exactly what they were, so
  no existing claim (`artefact: runtime, scope: "*/not-collected"`) stops matching.
- **Severity, one rule**: informational, unless the artefact is *required*, and
  then failing; always informational when an operator switched it off
  (`--no-runtime`, `--startup-restarts 0`).
- **Required**: `runtime` and `startup` by default; anything named in the new
  `HARNESS_REQUIRE_ARTEFACTS=<list>` (artefact names, `static` for the three
  image artefacts, `all`). `HARNESS_REQUIRE_STATIC=1` stays as an alias for
  `static`; the two add up, an unknown name is an error (exit 2), and the list
  only ever adds, so no setting can loosen a gate.

## What changes for a consumer

Nothing changes in a verdict, an exit code, a hunk's `artefact`, `scope`, `path`
or `severity`, or a claim, on any run that does not set the new variable. In
particular:

- **`runtime` and `startup` not-collected hunks are still failing by default.**
  The instruction was to make severity depend on "tools that may legitimately be
  absent locally", and to keep the old behaviour where that reading was the safer
  one. It is: both collectors run `docker`/`kubectl` against stacks the harness
  started itself, so an empty one is a fault (no such container, a probe that
  crashed), not a missing tool, and a nightly A/A whose ratchet is "0 artefacts not
  collected" (TESTING.md) would stop meaning anything if it went quiet. They are
  therefore *in the default required set*, and the old behaviour is what the new
  default reproduces. Making them informational by default is a one-line change
  (`DEFAULT_REQUIRED` in `src/not-collected.ts`) and a contract decision.
- **Text changed** (a `summary`, a `reasons` line, the run log; the contract only
  promises `artefact`, `scope`, `path` and `severity` of a hunk). A tool that
  matches a summary must match the new form. The static artefacts' `reasons` line
  lost its trailing "It was not compared."; the runtime and startup summaries lost
  the trailing `(side b)` for `on side b` inside the text.
- **`bus`** now has the same text in its run-log line, and a `capture.json`
  `bus.reason` of `no bus configured` / `external deployment` (it was
  `not collected: no bus configured`; `capture.json` is not part of the contract).
  It still adds **no hunk** to a report by default, because
  [docs/bus.md](../bus.md) promises that a run with no bus is byte-for-byte what
  it was. With `HARNESS_REQUIRE_ARTEFACTS=bus` a side with no bus is a failing
  `bus/not-collected` hunk (never asked of a live deployment).
- **New**: the environment variable `HARNESS_REQUIRE_ARTEFACTS`; per-artefact
  requirement (`=sbom` fails only the SBOM gap, where `HARNESS_REQUIRE_STATIC=1` was
  all three).
- `harness doctor` reads the same requirement for its grype check.

## Decisions for the owner

1. Ship the variable and the text change in 1.3.0 (this note, and a bullet under
   1.3.0 in [contract.md](../contract.md#changes)), or hold it for 1.3.1.
2. Keep `runtime` and `startup` required by default (the safe reading, done), or
   make them informational unless required.
3. Whether `bus` should get an informational hunk once a bus exists.
4. The change is in `src/compare/**`, an engine path: the CI engine guard asks for
   a harness version bump and the mutants re-run. `package.json` is not bumped
   here because this branch sits on the unreleased 1.3.0.

Nothing in it has been run against Docker. The unit tests drive each engine with
missing artefacts, and `tests/not-collected.test.ts` holds the four to one rule.

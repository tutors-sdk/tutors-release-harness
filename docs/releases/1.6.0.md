# Harness 1.6.0 (contract 1.6.0)

Follow-ups to [1.5.0](1.5.0.md), shipped one pull request at a time as harness 1.5.1 to 1.6.0.
Nothing in it is a break: a consumer written against 1.5.0 keeps working. It is a **minor**
release because `report.json` gains one optional field, `productionBuild`. The contract
changelog entry is in [../contract.md](../contract.md#changes).

## What is new

- **Which build production serves** (1.6.0, #47). Post-deploy mode asks production's reader
  for `/_app/version.json` and `/version` and judges the answer against the recorded
  candidate's commit: `match`, `differs` or `unknown`, with the build time when the build is
  unnamed. `report.md` and `report.html` get a "Production build" section, and anything but a
  match adds a line to `reasons`. It never changes the verdict and is never a hunk. The
  monorepo names its Netlify builds after `COMMIT_REF` since tutors-sdk/tutors-mono-repo#354,
  so a deploy made after it names its commit. `post-deploy.yml` also puts the line on the run
  page as a notice (#48).
- **Failed resources are named** (1.5.2, #46). A console "Failed to load resource" message
  carries the resource's URL (without its query), so a report says which resource failed, and
  two different failures on one page are two differences.
- **One open rollback issue, with the detail in it** (#44). `report.md` lists the detail of up
  to twenty unclaimed differences, collapsed and fenced. The monitor keeps one open `rollback`
  issue: a run whose differences it already carries adds nothing, and new differences are a
  comment on it.

## Hardening

- **Test coverage has a floor** (1.5.1, #36), re-measured in 1.5.3 when Vitest 5 began counting
  code that never runs: 82 / 76 / 82 / 83 (statements, branches, functions, lines). See
  [../../TESTING.md](../../TESTING.md).
- **Workflows** (#37): every action pinned to a commit, `actionlint` and `zizmor` as a required
  check, Dependabot for actions and npm, runners pinned to `ubuntu-24.04`, `main-preview.yml`
  run after the nightly, and one concurrency group per trigger for post-deploy.
- **Dependencies** (1.5.3, #45): `diff` 9 (its `structuredPatch` output checked byte-identical
  to 8's, so `dom` and `focus` hunks read the same), Vitest 5, ESLint 10, tsx and
  `@types/pixelmatch` 7. Dependabot PRs cannot pass the version guard on their own; a
  maintainer batches them (TESTING.md).
- **`main` is protected** by a ruleset: no deletion or force-push, changes through a pull
  request, and the five checks (typecheck, lint and tests; the A/A smoke run; workflow lint;
  masks in their own PR; mutants re-run) required.

## Behaviour that changes without a flag or field

- A post-deploy report names the failed resource in a console hunk, so a console hunk that
  was one difference per page can now be two.
- A post-deploy report has a "Production build" section and, unless production is the
  recorded build, one more line in `reasons`.

# Harness 1.36.2 (contract 1.36.0)

Main to RC says when production's pin is behind a release. A harness-only **patch**: no input,
output field, verdict, exit code, claims key, flag, workflow or mask changes, so the contract stays
at 1.36.0.

## Why

Main to RC takes production from the reader overlay's `newTag` on the monorepo's main. That pin moves
only when the `pnpm deploy:pin X.Y.Z` pull request merges (the monorepo's release/SOP.md, step 10).
On 15 October 2026 v17.0.0 was tagged and its images promoted, but main still pinned 16.2.2, so the
morning's forecast judged main against 16.2.2 and said nothing about it.

## What changed

- **`harness preview resolve`** (`src/ci/main-preview.ts`) reads the monorepo's tags. When a release
  tag (`vX.Y.Z`, never an `-rc`) is newer than the overlay's pin, it prints a
  `Production pin is behind a release` warning and adds it to the step summary. The run still
  judges the pinned production: the pin is what is deployed, and moving it is the monorepo's call.
- No warning when production is given by hand (`--a`), or when the tag lookup fails.

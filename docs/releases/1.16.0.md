# Harness 1.16.0 (contract 1.16.0)

The record keeps its rehearsals and ten days. The first step of the "Page" release, the overnight
readiness page: the page reads the `main-preview` branch, and before this the branch could not
be read ten days back, nor open the rehearsals its own score cited. The contract changelog entry
is in [../contract.md](../contract.md#changes). It is a **minor** release: no verdict, exit code,
`report.json` field or stable command or flag changes.

## What is new

- **The rehearsals are kept beside each forecast.** `harness reports keep --migration <dir>
  --upgrade <dir>` copies both rehearsals' `report.json`, `report.md` and `report.html` into the
  kept run's `migration/` and `upgrade/`. Main to RC passes the two it scored with.
- **The score's links open.** The kept `confidence.json` linked each rehearsal at
  `../../rehearsals/<mode>/<ranAt>-<mode>/...`, a directory of the runner that scored it and a
  14-day artifact, never the pages. The forecasts of 29 and 30 September said "the upgrade rehearsal
  FAILED: 778 finding(s)" behind a dead link. The kept copy now reads
  `upgrade/report.html#upgrade`; the same for `run.reports.migration` and `run.reports.upgrade`.
  Nothing else in the file changes.
- **Ten days, not only sixty runs.** `--keep-days n` is a floor under `--keep-last`: a run
  younger than `n` days is never pruned, whatever the count. Main to RC keeps
  `--keep-last 60 --keep-days 10`, so a day of runs by hand cannot push a night out.

## Upgrading

Nothing to do. Forecasts kept before 1.16.0 keep their dead rehearsal links; the next forecast
is the first with its rehearsals beside it.

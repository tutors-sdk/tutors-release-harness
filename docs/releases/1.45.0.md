# Harness 1.45.0 (contract 1.45.0)

The first lecturer journey. Rule 0588 has a lecturer and a student in one run, each in their own browser on the same
side. A **minor**: new pages, a second topic on the Rule journeys' course.

## Why

The proposal "Harness user journeys" (Rules 0582 to 0592) moves on to the lecturer. Its first lecturer journey is
Educator Control's content lock, which only shows up when two people are involved: the lecturer locks something and
the student stops seeing it. Before this release a journey had one browser, and the persistence stub read every table
as empty, so the student's browser could never see the lecturer's lock.

## What changed

- **Rule 0588** (exercises 0052, 0053, 0054): the lecturer signs in, locks Topic 2 in Educator Control and sees its card
  greyed out with Unlock. The enrolled student signs in and sees no Topic 2. The lecturer then turns on "Show locked
  content to students", and after a reload the student sees Topic 2 greyed out, labelled Locked, with no link. Three
  pages are captured: `reader-auth:rule-0588-lecturer-locked`, `-student-hidden` and `-student-locked-card`.
- **Two people in one journey.** In a Rule journey, any "the student ..." step can also be written as "the lecturer
  ...". The lecturer's steps run in a second browser context on the same side, signed in through the identity stub as
  `lecturer`. A step that names no one (`the page shows ...`, `the page is captured as ...`) runs in the browser of
  whoever acted last. `Journey.run` gains the optional `actors`, and `OnPage` the optional page to capture.
- **The persistence stub keeps the content locks.** It keeps the rows written to `tutors_content_locks` until the next
  journey's reset and returns them on reads (`eq` filters, `on_conflict` upserts, deletes). Every other table still
  reads empty, and the ledger records the same writes as before.
- **The Rule journeys' course** gains Topic 2, rebuilt from tutors-mono-repo `83d4ccf`. So the course page in 0584 to
  0587 shows one more card, the same on both sides.
- New steps: `switches on "..."` (also off), `the page shows no link starting "..."`, and
  `the card "..." shows the text "..."`.

## Proved

Run locally on images built from tutors-mono-repo main (`83d4ccf`):

- `--journey rule-0588-content-lock` passes on both sides, and its three screenshots show the greyed card with
  Unlock, the course page without Topic 2, and the greyed card labelled Locked.
- An A/A run with `--runs 3 --set rules,auth` is clean.

The lock code is the same at 17.0.0 (`packages/svelte/utils/rbac`, the card and Educator Control are unchanged
between v17.0.0 and main), so the mutants job's A/A against the production tag runs it too.

# Harness 1.35.3 (contract 1.35.0)

The signed-in journey works against SvelteKit 3 reader images again. A harness-only **patch**: no
input, output field, verdict, exit code, claims key, flag, workflow or mask changes, so the contract
stays at 1.35.0.

## Why

Mono-repo `main` moved to SvelteKit 3 and Better Auth on 13 October 2026. Kit 3's adapter-node has
no runtime `ORIGIN`: an app takes its origin from the request, and assumes https when no proxy says
otherwise. The harness publishes the signed-in reader as plain http on localhost, so the reader
believed it was `https://localhost:3103`, Better Auth refused the browser's `http://localhost:3103`
as an untrusted origin (`403 INVALID_CALLBACK_URL` on `/api/auth/sign-in/social`), and
`student-signs-in` timed out on both sides. The mutants self-test's A/A on `main` images was
therefore degraded, and every PR's mutants check went red.

## What changed

- **`fixtures/edge/forwarded.mjs`**: the edge a Tutors app expects in front of it, for one upstream.
  It adds `X-Forwarded-Proto: http` and passes everything else through.
- **`compose.harness.yaml`**: `reader-auth-edge-a` and `reader-auth-edge-b` publish
  `READER_AUTH_PORT_A`/`_B` and forward to `reader-auth-a`/`-b`, which no longer publish a port.
  The signed-in reader's environment sets `PROTOCOL_HEADER: x-forwarded-proto`. Kit 2 images still
  read `ORIGIN`, which wins over the header, so older images behave as before.
- **`fixtures/identity/README.md`** says how the browser reaches the signed-in reader.

The anonymous apps are untouched: their journeys do not compare origins. They will need the same
edge if a capture ever depends on the origin a Kit 3 app believes it has.

The A/A on Kit 3 images also needs `oauth-callback-state` (1.35.2, its own PR #110): Better Auth's random
OAuth state differs on every sign-in.

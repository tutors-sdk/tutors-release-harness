# Harness 1.30.0 (contract 1.30.0)

Course check and the course corpus. The contract changelog entry is in
[../contract.md](../contract.md#changes). A **minor**, for a new subcommand, a corpus file and three flags.
**The verdict never moves**: nothing in a run or the gate reads a capture or a check.

## Why

1.29.0 copies a live course to disk. Before a captured course goes into an A/B, something has to show it
loads. Plain HTTP can show the files are served, but not that the course loads: every reader page is
rendered in the browser (`ssr = false` across the reader), so `GET /course/<id>` answers the same shell
whether the course works or not. Only a browser shows a course loading.

## What is new

- **`harness course check --dir <capture> [--reader <url>]`**, two layers. Files: the course is served on
  `--port` (default 8190) by the fixture course server, and every captured file must come back with its
  sha256. Pages, with `--reader`: a fixed sample of the course's pages (`--sample`, default 20) is opened
  in Chromium, and each must show its title. Failed requests to the course host, page errors and the
  time to the title are recorded per page in `course-check.json`.
- **The course corpus, `fixtures/course-corpus/courses.yaml`**: at most five curated live courses, each
  with the reason it is there, and the `standard` (wit-hdip-comp-sci-2024 for now). `harness course
  capture --corpus` and `harness course check --corpus` read it; each course is captured alone, with no
  linked courses, so the corpus is exactly the courses it names.
- **`course-capture.yml`, job `corpus`**: captures the corpus, boots the stack from one tag, and checks
  every corpus course loads in side a's reader.

# Harness 1.20.1 (contract 1.20.1)

Which PR did it. The scorecard's unclaimed row showed "—" for every one of 899 differences while
`changes.json` already listed the files of all 67 PRs. A kept forecast now names, for each of its
causes, the PRs that could have made it. The second step of the "Explain" release. The contract
changelog entry is in [../contract.md](../contract.md#changes). A **patch**: no command, flag,
`report.json` or index field, verdict, Gate or exit code changes; only what a kept forecast leads
with.

## What is new

- **Causes and the PRs behind them**, in a kept forecast's lead, right after "New since the last
  forecast" (`src/changes/attribute.ts`).
- **By delta.** A cause the previous forecast beside the same production did not have can only
  come from the PRs merged since: those in tonight's `changes.json` and not in that forecast's,
  matched by PR number. Of those, the ones whose files touch the cause's paths are named, or all of
  them when none do. On the kept forecasts: on 28 September (08:59) the new cause "request no
  longer made on b: GET /global.css" against #331, one of the three PRs merged since; on
  30 September the new "video.mov status changed" against #373, one of two.
- **By path**, for every other cause: a page, log, metric or journey table against the app's own
  source (direct) and then `packages/**`; an image against a Dockerfile (direct) and then a package
  manifest or the lockfile. Documentation, tests and workflows never match. The first three PRs of
  each cause are named, most direct files first: "image-manifest: # layer(s) on a, # on b" names
  #279, #282 and #143, the three PRs that touched a Dockerfile; the page causes name the Paper
  rebuild (#313) first.
- What it does not do: path matching names a PR for every one of the 19 causes on each forecast,
  but only 2 or 3 causes a night narrow to three PRs or fewer. The others are a ranked list to
  start from, never a verdict.

## Upgrading

Nothing to do. A forecast kept beside one kept before 1.20.0 compares causes recomputed from that
report's unclaimed set.

# Harness 1.52.0 (contract 1.52.0)

Secrets in responses. A **minor**. Part of the harness hardening plan (production-readiness additions, tranche 1, item D3).

## Why

The harness looked for secrets only in an image's environment and layer history. Nothing looked at what an app sends the browser, and the one place a leak would show was made blind on purpose: the collector redacts JWTs, `apikey=` values, bearer tokens and Supabase keys before anything keeps the text (`src/normalise/redact.ts`), so a report never republishes one. That is right for reports, and it means a service-role key served in a page would be redacted before any engine could see it.

## What changed

- `src/collectors/secrets.ts`: a raw scan, run by the browser collector before redaction, over the accessibility tree, the document's response headers, every response URL, every console message and page error, and the body of every HTML document and JSON response. It keeps a name and a reason, never the value.
  - **Canaries**: every `PRIVATE_*` value `compose.harness.yaml` sets (the stack's own server-only secrets, not real ones).
  - **Patterns**: the secret-shaped values image-hardening already knows (AWS, GitHub, GitLab, Slack, npm, Stripe, a private key), and a JWT only when its payload's role is `service_role` or `supabase_admin`. A signed-in student's session token is meant to reach their browser.
- Each page capture keeps `secrets: [{ source, name, why }]`.
- `src/compare/secrets-in-response.ts`: the new `secrets-in-response` artefact judges b alone. Each (page, source, name) is `<page key>/<source>/<name>`, failing, "(production too)" or "(new on b)"; a clean b is one `summary`. A capture recorded before 1.52.0 has no scan and says nothing.
- `mutants/mutants.yaml`: `secret-in-body`, an edge mutant that serves the reader's `PRIVATE_AUTH_SECRET` in an inline JSON script at the end of every server-rendered page.

## Level

**Informing**, with no date: reported, claimable, never gates. The plan wants it blocking; by the harness's own rule it is promoted once the soak has seen its mutant caught. No verdict, Gate, score or exit code moves.

## Not done

The plan named the persistence stub's service-role key as the canary. The harness stack sets no service-role key today (the apps it runs do not need one), so the canaries are the `PRIVATE_*` values it does set; a service-role JWT is caught by its role wherever it appears.

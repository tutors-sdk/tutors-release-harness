# Harness 1.16.1 (contract 1.16.1)

New since the last forecast. The 29 September forecast had 899 unclaimed differences; what a
morning reader needed was the 11 that were new and the 5 that were gone since the night before.
Every kept forecast now says so. The second step of the "Page" release, the overnight readiness
page, which will read these counts. The contract changelog entry is in
[../contract.md](../contract.md#changes). A **patch**: no command, flag, `report.json` field,
verdict or exit code changes; the new index field is optional.

## What is new

- **`delta` on each kept release run** in `reports/index.json`: `new`, `gone` and `byArtefact`
  against the previous kept run beside the same baseline (`against` names it: its id, when it
  ran, its candidate and the harness that judged it). When production moves, the delta starts
  again (`against: null`), so two baselines are never compared.
- **The same difference across nights** is the same artefact, scope and summary with every
  number masked: a hunk's id carries a counter, and "+51 −25 lines at line 4" becomes "+52 −25"
  without anything new having happened. Counted as multisets, so new − gone is always the change
  in the unclaimed count. On the kept forecasts: +28/−1 (27 to 28 September, 03:45), +3/−2,
  +11/−5, and +1/−696 on 30 September, when the sbom claim landed.
- **The kept report leads with it.** Right under the Gate, "New since the last forecast": the
  counts, the new differences (the first 15, each linked to its row) and the gone ones (the first
  10). It says when the previous forecast was judged by another harness version.
- **`reports-index.schema.json`**: the index's first schema.

## Upgrading

Nothing to do. Runs kept before 1.16.1 have no `delta`; the next forecast is compared with the
newest kept one beside the same production, whichever harness kept it.

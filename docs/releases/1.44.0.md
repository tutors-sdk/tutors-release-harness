# Harness 1.44.0 (contract 1.44.0)

The Rule journeys' course. Four more Rule journeys, on a second fixture course built for them. A **minor**: a new host
port, new pages.

## Why

The proposal "Harness user journeys" (Rules 0582 to 0592) needs a course the fixture course is not: one that asks for
sign-in and lists who may read it, with a quiz, a notebook and a calendar. 1.43.0 landed 0582 and 0583 on the fixture
course; this release lands the student journeys that need the rest.

## What changed

- **`fixtures/course-server/rules-course`**, built with the monorepo's own scaffolder and generator
  (`rules-course-build/build.ts`, `scripts/build-rules-course.sh`) and committed. It is signed in and private (only
  `harness-enrolled` is on the whitelist), has a two-question quiz, a notebook, a calendar on fixed dates around the
  harness clock, and its LLM page linked. The course server publishes it on 8081 (`RULES_COURSE_PORT`), on compose
  and beside kind.
- **Rule 0584** (exercises 0047, 0049, 0050): as the enrolled student, a talk's next slide, a notebook's next cell, and a
  quiz answered, revisited and submitted.
- **Rule 0585** (exercises 0037, 0038, 0039): the dark appearance and the Dyslexia theme survive a reload.
- **Rule 0586** (exercises 0011, 0267): the stub student, whom the course does not list, is sent to My courses at
  sign-in and again by the course's address.
- **Rule 0587** (exercises 0042, 0284): the calendar filtered to assessments, then the course's page for LLMs.
- **Steps.** Open a talk, note, notebook or quiz; go back to a topic; reload; choose a radio in a group; select in a
  combobox; check a combobox's choice, a table's rows, a text, a status (present even when visually hidden), and that
  something is not shown; sign in and be turned away. `@course-rules` picks the course, and a `;` in the scenario's
  "(exercises Rules ...)" starts a note.

- **Sign-in under the limiter.** Six Rule journeys after the `auth` one met the reader's limiter even when paced. The
  quiet gap now runs from when a sign-in landed, and a refused sign-in is tried once more after a whole gap; a second
  refusal fails the journey and says so.
- **The course server's mount.** Compose mounts `fixtures/course-server`, not each course: a course rebuilt while a
  stack is up is served as rebuilt, not as an empty folder (every page of it a 404).

## Proof

A local A/A of main's images (`--runs 3 --set rules,auth`: the `auth` journey and the six Rule journeys) is PASS and
clean.

## What it found

The LLM page linked every download over https, so on a course served over http (local and test courses) each link was
dead: tutors-mono-repo#506 (Rule 0600), for Leigh to merge.

The Preferences menu's button is "Open Theme Menu" up to 17.0.0 and "Preferences" after tutors-mono-repo#505, so the
preferences journey opens it by either name: a run against the production tag would otherwise fail on both sides.

## What a consumer does

Nothing. A local stack publishes one more host port (8081); `--port-offset` moves it with the rest.

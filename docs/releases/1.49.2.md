# Harness 1.49.2 (contract 1.49.2)

A PR's CHANGELOG hint is read from the title GitHub has now. A **patch**.

## Why

The 21 Oct forecast (`sha-260bdc4` beside 17.0.0) still owed 19 differences after #518's and #519's titles were corrected to `(persistence, sbom, logs)` on 20 Oct. `harness changes` took each PR's title from its merge commit, which keeps the title the PR had when it merged, and the title's hint wins over the body's CHANGELOG line. The body was already read live (1.41.0), so a corrected body counted and a corrected title never did.

## What changed

- `src/changes/github.ts`: the body source also gives the PR's current `title`, from the same `GET /repos/{repo}/pulls/{n}` request; `readTitles` reads them, and a PR GitHub cannot answer for keeps its merge commit's title.
- `src/changes/signals.ts`: `prs[].declares` reads the hint from the live title when there is one. `prs[].title` stays the merge commit's.

No verdict, Gate or exit code rule moves.

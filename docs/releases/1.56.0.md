# Harness 1.56.0 (contract 1.56.0)

All eight score dimensions measured. A **minor**. Part of the harness hardening plan (production-readiness additions, tranche 1, item E1).

## Why

The Release Confidence Score has eight dimensions, but a plain `harness release` measured four: claim coverage, noise health, statistical margin and rehearsals. Test signal, traceability and post-deploy history needed input files nobody passed, although every one of them already exists: the monorepo's quality record on its `quality` branch, the PRs and claims of the release, and the post-deploy runs the harness itself keeps. The RCS was four-eighths of what it was designed to be.

## What changed

- **Traceability** (`src/score/traceability.ts`): `harness changes` writes a `traceability` block into `changes.json`. It has one entry per feat or fix PR, with the EARS feature file the PR changed or the Rule its title cites. With the new `--claims <claims.yaml>`, a PR that declared an observable change also gets whether a claim names it, and claims naming PRs outside the release are listed. `harness confidence` reads the block from `--change-risk` when no `--traceability` is given.
- **Test signal**: `harness release` finds the monorepo's quality record, `quality/<sha>.json`, for the candidate's commit or the newest of the 60 before it. It reads it from the checkout's `quality` branch, fetching it once. `release.yml` reads the same record from GitHub, as `main-preview.yml` already did.
- **Post-deploy history**: `harness release` takes the newest post-deploy run under its output root (what `harness local watch` writes). `release.yml` downloads the newest kept `post-deploy-report` artifact, which needs `actions: read` on the scoreboard job.
- The score stage's note says what it found for each input, or why it found nothing. A missing input stays **not measured**, never assumed clean.

## What to expect

Releases now show more of their score, and some will drop. Replaying 16.2.2 to 17.0.0 gives 52 feat or fix PRs. Only 17 of them changed an EARS feature file or cited a Rule; the other 35 include 17 features. As designed, a feature with no EARS Rule (and an orphan change) breaches traceability's floor, which caps the RCS at 74. The board names every PR that cost points, so the drop is explained, not hidden.

## Level

Score only. The RCS is advisory: no verdict, Gate or exit code moves.

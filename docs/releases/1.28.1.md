# Harness 1.28.1 (contract 1.28.1)

A network mask may make two response statuses count as one. The contract changelog entry is in
[../contract.md](../contract.md#changes). A **patch**: no input, output field, verdict or exit code
changes, and **no mask is added here**.

## Why

The 2.0 soak broke on 2026-10-02 and 2026-10-03 on the same page, `reference:note`, from the same
image on both sides: `GET {{course}}/topic-07-reference/note-1/img/video.mov status changed: 200 → 206`.
Chromium fetches a video either whole (200) or by range (206), depending on what it has buffered, so
the status is the browser's choice, not the release's. The network engine already counts a streamed
media file once however many range requests it took; it still compared that one status.

No existing mask could hide it narrowly. A URL rewrite leaves the status alone, and `drop: true`
removes the request, so a video that started answering 404 would vanish too.

## What is new

- `status: [206, 200]` on a `network` pattern mask: on the requests whose URL matches, a response
  answered with any listed status is recorded as the first listed one, on both sides. The URL is kept,
  and a status outside the list (404, 500, 416) still shows as `status changed`.
- The schema refuses it with `header`, `drop` or `replace`, on any other artefact, without a `pattern`,
  or with fewer than two different statuses.
- `tests/network-status-mask.test.ts` holds it with a test-only mask: 200 against 206 either way round
  is clean, and 404, 500, 416, 304, a lost request, a new request, a changed content type and the same
  200/206 on another URL all still show.

The mask that uses it, and the console mask for Chromium's compute-pressure message, land in their own
PR, as `src/ci/mask-change.ts` requires.

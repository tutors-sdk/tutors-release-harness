# Harness 1.28.1 (contract 1.28.1)

Claims: known and gaps. The contract changelog entry is in [../contract.md](../contract.md#changes).
A **patch**: three optional fields on each forecast in `readiness.json`, and pages. No verdict,
Gate or exit code moves.

## Why

Every kept forecast's report already counts both sides: "Claimed differences (701)", "Unclaimed
differences (204)", "Claims owed (18)" and the claim hygiene. The landing pages showed only the
gaps. A reader could see what the next release owes, but not what the claims already cover, or
whether those claims are healthy.

## What is new

- **A Claims column and coverage** in the readiness page's night table: claimed beside unclaimed
  on every forecast, and claimed / (claimed + unclaimed). On the 3 October forecast: 701 claimed,
  204 unclaimed, 77% covered.
- **Claims: known and gaps** ([readiness.html#claims](https://tutors-sdk.github.io/tutors-release-harness/readiness.html#claims)),
  before the control chart. For the latest forecast it shows the known side and the gaps per
  artefact (sbom, network, dom, screenshot, focus, logs, headers, image-manifest, axe, persistence,
  console, ...). Each number links to its first row in the kept report. It also shows the
  claims owed, linked to the drafts, and the claim-hygiene findings: a claim too broad
  (more differences than the threshold), a broad claim with or without approval, a stale claim,
  an expired one. Each finding links to the report's own section.
- `readiness.json`: each forecast's `claimed`, `coverage` and `claims`
  ([readiness.schema.json](../contract/readiness.schema.json)).
- The A3's goal gains **Claims: known and gaps**, and the landing page's readiness card leads with
  the same sentence.
- The landing page no longer scrolls sideways on a phone: a long path in the latest forecast's
  change-risk list now wraps.

Advisory, like the rest of the page: the counts are read from the kept `report.json` and never
change the Gate.

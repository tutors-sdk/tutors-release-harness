# Harness 1.33.0 (contract 1.33.0)

Real courses held to the tutors.json schema. The contract changelog entry is in
[../contract.md](../contract.md#changes). A **minor**, for a new check field and new `a3.json` fields.
**The verdict never moves**: the Gate, the score and every exit code of a run read nothing new, and
neither does `harness course check`'s exit code.

## Why

Mono-repo #421 gave `tutors.json` a schema: `TUTORS_JSON_SCHEMA` in `@tutors/tutors-types`, published as
`tutors-json.schema.json`, which the generator differential holds every corpus course to (Rule 0263).
That says what the generator on main promises to write. It does not say how far the courses lecturers
have already published are from that promise. The harness captures those courses, so it can say.

## What is new

- **`tutorsJson` in `course-check.json`.** `harness course check` holds the captured `tutors.json` to the
  schema, with or without a reader: whether it conforms, how many problems it has, and the first ten,
  each named by the ids on its path (`/los/[topic-01]/los/[note-01] has a field the schema does not
  allow: pdf`), worded as the mono-repo's differential words them.
- **A "tutors.json schema" column on the A3**, under Real courses, with the first problems for a course
  that does not conform, and a count under the table.
- **`fixtures/tutors-json/`** holds the schema, copied verbatim from the mono-repo (#421, commit in
  `source.json`), with how to refresh it.

## Reported, never a fail

Courses written by older generators (before gen-lib 4.2.20, for one) break the strict schema, and the
reader still opens them: the mono-repo's Rule 0270 loads tutors.json from seven generator releases.
So a course that does not conform is never a state, a goal row, a fact or an exit code. It is a reading
of how far real courses are from what main writes, for whoever decides when to tighten the reader or
regenerate a course.

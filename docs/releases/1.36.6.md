# Harness 1.36.6 (contract 1.36.0)

The persistence stub accepts Supabase's per-topic HTTP broadcasts. A harness-only **patch**: no input,
output field, claims key, flag, workflow or mask changes, so the contract stays at 1.36.0.

## Why

Since mono-repo #470 bumped supabase-js, the reader sends some broadcasts with `channel.httpSend()`,
which posts to `/realtime/v1/api/broadcast/<topic>/events/<event>`. The stub only knew
`/realtime/v1/api/broadcast`, so it answered 404 and the client logged "httpSend() requires Realtime
server v2.97.0 or newer". That put 8 console errors in every reader comparison (the A3 of 15 Oct 2026
counted them among the unclaimed differences). Hosted Supabase serves the path, so the errors came
from the harness, not from Tutors.

## What changed

- `fixtures/persistence/stub.mjs` answers 202 to a POST on either broadcast path and records neither,
  as before.
- `tests/fixtures.test.ts` covers the per-topic path.

# Harness 1.40.0 (contract 1.40.0)

The A3 reads post-deploy over the release production serves now, every control chart carries its figures, a fix on
main reads as good news, and a countermeasure says how a release will show it works. A **minor**: two optional 5 Whys
fields and new optional `a3.json` fields; no verdict, Gate or exit code moves.

## Why

On 16 Oct 2026 the A3's post-deploy tile and its Pareto counted every failed post-deploy run GitHub keeps, back to
the 16.2.2 rollback of 27 Sep, and named rollback issue #38 (16.2.2) as this release's. The current red began at
19:10 on 15 Oct, ten hours after 17.0.0 was deployed, when post-deploy first compared production with 17.0.0's
recorded capture: Netlify sends no immutable `Cache-Control` on `/_app/immutable/*` (the monorepo's `netlify.toml`
sets it on `/build/*`; tutors-mono-repo#500), and the images do. The control charts showed no numbers, so "above
the UCL" could not be read. A fix on main read "undecided", which sounds like something wrong. And "3
countermeasures open" did not say what a countermeasure is, or that two were already built.

## What changed

- **Post-deploy, the release timeline.** The tile, the root cause answer, the line-stop Pareto and the facts read
  only the runs from the newest `deployed` dispatch on. The tile names the release, when the red began, the newest
  run and the root cause. A rollback issue opened before that deploy is named as "from an earlier release", never as
  this release's.
- **Control charts with figures.** Each chart labels its UCL, centre and LCL in ms and main's newest median, and the
  reading works the limits out: centre, the mean moving range, UCL = centre + 2.66 × mR̄. The section says in plain
  words what the band, the UCL and the LCL mean.
- **Fixed on main is good news.** The strip reads "good news, never a failure"; a fix's chip reads "fixed" or
  "fixed, explained"; a claim is an optional note that the fix was meant.
- **Countermeasures you can check.** A 5 Whys gains `In place` (where it was built) and `Check` (what a release must
  show, then what the last release showed). The tile says what a countermeasure is and splits the count: built and
  waiting on a release, not built, overdue, verified; it links each one. `why check` refuses a `Verified by` with no
  `Check`. The register closes the 16.2.2 rollback countermeasure in 17.0.0 (post-deploy read "production build:
  match") and shows the other two in place and waiting; 17.0.0 did not show the SBOM claim guidance working (212 SBOM
  differences unclaimed, one claim covering 696).
- **`post-deploy/claims.yaml` is empty.** Its five claims explained the untracked build of issue #38, which 17.0.0
  replaced.

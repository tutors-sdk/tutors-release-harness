# Harness 1.62.0 (contract 1.62.0)

A claim that matched nothing because production already ships what it claims no longer fails a forecast. This is a **minor** release: what counts toward PASS, explained widens again, and the ledger gains `shipped`.

## Why

Every Main to RC forecast beside 17.1.0 since 4 Nov 2026 kept Gate FAIL, although the code had already explained every difference. On 9 Nov ([run 42625309091](https://github.com/tutors-sdk/tutors-release-harness/actions/runs/42625309091), `sha-41243b2` beside 17.1.0) all 20 unclaimed differences were pinned on the PR that made them (#589: 12, #571: 8) and none was unexplained. The run had a second reason, "10 claim(s) matched nothing". `declaredPass` accepted unclaimed differences as the only reason, so that second reason kept the FAIL.

Those ten claims are the 17.1.0 release's own claims, still in the mono-repo's `release/claims.yaml`: the Live activity route and its tables (#481), the Node base image pin (#541), the time-data log fields (#320), and the signed-in student and whiteboard routes (Rules 0068, 0072). Each matched differences in the kept forecasts beside 17.0.0. 17.1.0 shipped them, so beside 17.1.0 nothing is left to match. Leigh (9 Nov): "We have the code, the PR and the reference so this shouldn't cause a fail when we know what happened."

## What changed

- `src/changes/explain.ts` `shippedClaims`: a stale claim is shipped when a kept run beside an earlier production matched it (`how: "seen"`, with that production and when), or when every PR its reason names is outside the run's range, so merged before production's tag (`how: "named"`). The ledger lists them as `shipped`.
- `declaredPass`: the reason "N claim(s) matched nothing" no longer blocks PASS, explained when every stale claim is shipped. The note then ends with "N claims (…) matched nothing because 17.1.0 already ships what they claim: archive them from release/claims.yaml." A forecast whose only reason is shipped claims passes with "every difference is claimed".
- A3: "Why do claims match nothing?" tells shipped claims (archive them) apart from the rest. When every difference is pinned and a stale claim nobody saw ship is what fails, `gateWhy` says so, not "FAIL only because N differences are not claimed yet".

## Still a FAIL

- A stale claim that no kept run saw match, and that names a PR in the range or no PR at all: a claim to remove, or a difference that did not happen.
- A release candidate: the release author still archives shipped claims and pastes the new ones.

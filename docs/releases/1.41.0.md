# Harness 1.41.0 (contract 1.41.0)

A difference its own PR declared is explained, not owed. The monorepo's CONTRIBUTING.md (Changelog Entries) asks each PR
to name the artefacts it will move in its CHANGELOG line, `(axe, dom)`, and the release author turns that line into a
claim when the release is cut. The forecast now reads that line, so a contributor who said it is never asked for a
follow-up PR to say it again. A **minor**: new optional fields in `changes.json` and `a3.json`; no verdict, Gate or exit
code moves, and the release gate still needs every claim.

## Why

On 17 Oct 2026 the Main to RC forecast of `sha-83d4ccf` failed on 12 unclaimed differences, all one change:
tutors-mono-repo#505 renamed the Preferences button from "Open Theme Menu" to "Preferences" (axe 4.14,
`label-content-name-mismatch`). The harness named #505 as the only PR that could have made them and drafted two claims
with `rule: "????"`, as if nobody had said the change was meant. #505 had: its CHANGELOG line ends `(axe, dom)`. What it
did not say is that the keyboard order (`focus`) would move too, and that was the one thing to fix.

## What changed

- **What a PR declares.** `harness changes` reads each PR's body with the token it already uses for reviews, and
  `changes.json`'s `prs[]` gain `declares`: the artefacts its title's hint names, else its body's CHANGELOG line
  (`- [x] CHANGELOG: \`<entry> (axe, dom)\``, as the PR template asks; the template's unticked example is never read).
- **The gap, explained.** A difference contributed by a PR whose line names its artefact is its own row, **declared by
  its PR**. A contributed row whose PR wrote a line that missed what moved says so: "#505's CHANGELOG line says (axe,
  dom); focus moved". On 17 Oct: 17 differences, claims explain 5, #505 declared 10, #505 contributed 2.
- **The Gate's sentence** on the A3 says the forecast fails only on what nobody declared, and that declared differences
  are owed nothing on main. When every difference is declared it says the FAIL is only for want of the claims the
  release will carry.
- **The forecast's report.** "Causes and the PRs behind them" marks a new cause as declared by its PR, or names the PR
  whose line missed it. Claims owed draft a declared cause with `reason: "CHANGELOG: <entry> (#505)"` and no Rule to
  name, ready to paste when the release is cut; the heading counts them apart ("Claims owed (1, and 1 declared)").

A declaration is read live from the PR, so correcting a merged PR's CHANGELOG line (#505's to `(dom, focus)`) is enough
for the next forecast: no follow-up PR. A cause matched by path only (one not new since the last forecast) is never
declared in the report's cause table, since a PR that touched the shared packages weeks ago says nothing about tonight;
the A3's ledger, which follows each difference back to the night it appeared, keeps it declared.

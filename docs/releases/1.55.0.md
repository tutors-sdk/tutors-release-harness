# Harness 1.55.0 (contract 1.55.0)

The header contract. A **minor**. Part of the harness hardening plan (production-readiness additions, tranche 1, item D1).

## Why

`headers` fails when a header changes between production and the candidate. It says nothing when both lack one, and today every app lacks a Content-Security-Policy and HSTS from the container path. The monorepo already writes down what every app must send, `tests/security/header-contract.json`, and checks its own images against it in its PR smoke test with a list of known gaps. Nothing in the release harness read it.

## What changed

- `src/compare/headers-policy.ts`: the new `headers-policy` artefact. Every document b served (a page with response headers) is judged against the contract, its app read from the page key:
  - `<app>/<header>`: the header is missing, or not what the contract asks (`equals`, ignoring case and space, or `matches`, a regular expression).
  - `<app>/cookie/<name>`: a session cookie set without `HttpOnly` or without `SameSite`. `Secure` is not judged: the harness stacks are plain HTTP.
  - `<app>/summary`: the app holds the contract.
  - Each finding says "(production too)" or "(new on b)".
- `--header-contract <file>` on `harness run` and `harness compare`; `harness local gate` and `harness local release` take it too, and `local release` finds it in the monorepo checkout. An unusable file is exit 2 before any stack starts.
- `release.yml` and `main-preview.yml` fetch `tests/security/header-contract.json` at the same ref as `release/claims.yaml`; none (a 404) judges nothing.

## What to expect

Every forecast will carry `content-security-policy` and `strict-transport-security` findings on all four apps, "(production too)", exactly the gaps the monorepo's `known-response-gaps.txt` lists. They go away when the apps (or the edge in front of them, for HSTS) send them.

## Level

**Informing**, with no date: reported, claimable, never gates. The plan makes it blocking once the monorepo ships a CSP (its hardening Stage 1.2), and only after a `dropped-csp` mutant is caught; there is no CSP to drop yet, so that mutant waits for it.

# Harness 1.32.0 (contract 1.32.0)

What a student would notice on real courses if main were released. The contract changelog entry is in
[../contract.md](../contract.md#changes). A **minor**, for new check fields, a flag, new `a3.json`
fields and a workflow trigger. **The verdict never moves**: the Gate, the score and every exit code of a
run read nothing new.

## Why

Main is the release candidate: students meet it only once it is released, so checking it on real courses
is a release decision. 1.31.0 asked one shallow question of each course, whether its pages show their
titles, and the standard course, a portfolio of links, gave it one page to open. A release can break a
lab's images, a step's navigation or a page's headings and still show every title.

## What is new

- **Five courses.** The standard plus four modules, chosen for size and shape: programming (489 learning
  objects), full-stack-1 (529), comp-sys (315, another author) and databases (381).
- **Each page as a student meets it** (`experience` in `course-check.json`): the visible text, the
  headings the author wrote in the page's markdown (not the reader's own, which change with its design), the
  course images that did not load, the links to pages of the course that do not exist, and
  serious or critical accessibility violations (axe).
- **Journeys, clicked** (`--journeys`, default 2): the course page, a topic, a lab and its steps, each
  reached by clicking its link on the page before. Opening a page by its address does not show that a
  student can get there.
- **Production against main, page by page** (`src/course/compare.ts`). Worse on main: a page that does not
  load, more broken images, a failing course file, a new console error, a broken link, a lost heading, a
  quarter less text, a new serious accessibility violation, or a journey main clicks less far through.
  Better on main is the same the other way round. `harness course compare --a <production's checks>
  --b <main's checks>` says so on the command line and exits `1` only when main is worse: production's own
  failures (it fails pages today) no longer turn the corpus job red.
- **The A3** names each course worse on main with its pages and reasons, adds the goal row "Nothing a
  student uses is worse on main (real courses)", and says when the courses and the forecast describe
  different commits.
- **The same main as the forecast**: the corpus job runs straight after each Main to RC.

Also: mono-repo main sha-3b9e456 (#400) moved a topic's title from the page to the side menu's card, so
two journeys timed out on main on both sides. They now find it there as well, as the mono-repo's own
journey does.

Times stay a reading beside each other, one check per side: not a benchmark.

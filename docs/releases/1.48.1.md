# Harness 1.48.1 (contract 1.48.1)

A cause first measured is not pinned on the newest PRs. A **patch**: the lead and the A3 gap ledger say who could have
made a difference; nothing that judges reads them.

## Why

The 18 Oct 2026 Main to RC forecast (sha-83d4ccf beside 17.0.0) named #505 for two persistence causes,
`realtime_claim_live_publish` and `realtime_watch`, because the last forecast of another build (sha-c867ee8, 16 Oct)
lacked them and #504 and #505 were the only PRs merged since. That forecast ran none of the Rule journeys (0582 to 0592
shipped from 1.43.0), so lacking those differences told it nothing: they were first measured, not first made. They are
the Live budget calls of #481, which merged before it.

## What changed

- **The lead** (`report.md`, `report.html` of a kept forecast): a cause whose every difference is on a Rule journey the
  previous forecast did not run is matched by path over the whole range, like a cause that was already there, and its
  row says `first measured by Rule journey 0589, which the last forecast did not run: matched by path over the whole
  range`. On the 18 Oct forecast both persistence causes now name #478 and #481, not #505. A cause with a difference
  on any other page stays new.
- **The A3 gap ledger** (`src/changes/explain.ts`): a difference on a Rule journey the forecast before it did not run
  reads that forecast's whole range, as the oldest kept forecast does. Too many PRs to name gives the new unexplained
  reason `first-measured`.
- Which journeys a forecast ran is read from its timing control chart (`timingControl.journeys`, since 1.39.0). A
  report kept before that records none, and every journey counts as run, as before.

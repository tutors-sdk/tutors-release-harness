# Harness 1.29.0 (contract 1.29.0)

Course capture. The contract changelog entry is in [../contract.md](../contract.md#changes). A
**minor**, for a new command and its flags. **The verdict never moves**: nothing in a run or the
gate reads a capture.

## Why

Every run reads one course, the scaffolder's default with two topics. A real course is hundreds of
labs, talks and images, and it lives on Netlify, where it can change or disappear. To benchmark
the reader hard against a known working course, the course has to be local files, pinned.

## What is new

- **`harness course capture --course <https://tutors.dev/course/<id> | id>`** reads the course's
  `tutors.json` from its host as the reader does, every file it names on that host (images, PDFs,
  archives, the `img/` and `archives/` its markdown names) and, to `--depth` (default 1), the
  Tutors courses its `web` learning objects link to. Anonymous GETs only: a course behind a sign-in
  is recorded as not public. Each course is written byte for byte to `<out>/<id>/` with
  `course-capture.json`, every file's size and sha256; `<out>/courses.json` lists the courses.
  `--out` defaults to `HARNESS_HOME/courses/<id>`. `--concurrency`, `--max-file-mb`, `--skip-ext`,
  `--dry-run`, `--force`, `--strict` and `--json` as in [course-capture.md](../course-capture.md).
- **`harness course verify --dir`**: is a capture still what was captured (exit 1 when not).
- **`harness course serve --dir [--port 8080]`**: one captured course folder on
  `fixtures/course-server/serve.mjs`; the reader's course id is `localhost:<port>`.
- **`course-capture.yml`**: captures `wit-hdip-comp-sci-2024` on GitHub's runners on demand,
  weekly and on a pull request that changes `src/course/`, and keeps the manifests as an artifact.

## Not in this release

Serving a capture inside the compose stack, and journeys for it: that is a fixture change of its
own, with its own version bump ([course-capture.md](../course-capture.md#into-an-ab)).

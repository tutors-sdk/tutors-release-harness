# Harness 1.46.0 (contract 1.46.0)

Tutors Live with a student in it. Rule 0589 has the lecturer find a student who shares presence in Tutors Live. A
**minor**: two new host ports and new pages.

## Why

Until now the harness only opened Live empty (`live-loads`). In compose, Live runs in anonymous mode, which reads
nothing. A lecturer opens Live to see who is working and on what, and the harness could not compare that view.

## What changed

- **Rule 0589** (exercises 0330, 0335; the monorepo's presence-tracking and student-engagement features): the stub
  student signs in to the fixture course and opens Lab 1 with presence sharing on. The lecturer opens Tutors Live, the
  student reloads the lab, and Live's Courses tab counts 1 course and its Students tab lists Harness Student on Lab 1. Two pages are captured:
  `live-auth:rule-0589-courses` and `live-auth:rule-0589-students`.
- **`live-auth-a` and `live-auth-b`**: a second Live on each compose side, with anonymous mode off and the side's
  persistence stub as its Supabase, on host ports 3105 and 3205 (`LIVE_AUTH_PORT_A`/`_B`, so 22 host ports in all).
  Live has no sign-in, so the lecturer's browser simply opens it. `StackUrls.liveAuth` is optional; kind runs no
  `live-auth`, and there 0589 fails with a step that says so.
- **The persistence stub keeps `tutors-connect-latest`**, each student's latest learning object, and answers `gte`,
  `order` and `limit`. That is what Live reads to show who is online when no Realtime message reaches it, which in the
  harness is always. The reader's online list reads the same table, so 0583's list now comes from stored activity too,
  the same on both sides.
- **The persistence stub relays Realtime broadcasts when a journey asks** (`POST /_harness/relay`, off again at
  reset): a broadcast posted over REST or pushed on a socket reaches the other sockets joined to its topic. Live up to
  17.0.0 learns of a student only from the reader's `lo-event` broadcast, so in 0589 the student reloads the lab once Live
  is open, with the relay on; that is what lets the journey run against the production release in the mutants self-test. No other journey
  turns it on.
- **The mutants self-test** runs its A/A on the base with the Rule journeys, as before, but each mutant's run without
  them: no mutant needs them to be caught, and ten more journeys per mutant took the self-test past its two hours.
- New steps: `the lecturer opens Tutors Live`, `the persistence stub relays Realtime broadcasts`,
  `the lecturer looks at their own browser`.

## Proved

Run locally on images built from tutors-mono-repo main (`83d4ccf`):

- `--journey rule-0589-live` passes on both sides, with one course and Harness Student on Lab 1. The mutants self-test proves it on 17.0.0.
- An A/A run with `--runs 3 --set rules,auth` is clean.

Behind an HTTP proxy, a local run needs `.harness.test` in `no_proxy`. Otherwise Chromium sends Live's Realtime
socket through the proxy, which answers 403 (the same on both sides). CI has no proxy.

## What a consumer does

Nothing. A local stack publishes two more host ports, and `--port-offset` moves them with the rest.

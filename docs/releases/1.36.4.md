# Harness 1.36.4 (contract 1.36.0)

The upgrade rehearsal judges the rollout only, as documented. A harness-only **patch**: no input,
output field, claims key, flag, workflow or mask changes, so the contract stays at 1.36.0.

## Why

The 17.0.0-rc.1 gate run (15 Oct 2026) failed its upgrade rehearsal with "983 finding(s) during the
rollout". Upgrade mode captures a and b around the rollout and compares them, and the gate counted
every unclaimed difference in that comparison as a rollout finding. The workflow passes no claims to
the rehearsal, so every change between 16.2.2 and 17.0.0 (the DOM, SBOM, headers and so on) counted,
and a release with many changes could never pass.

## What changed

- `gate()` in upgrade mode fails only on `upgrade` hunks: a failed or 5xx request during the rollout,
  no request served by b, or no load at all (`docs/modes.md`, "upgrade").
- The other differences stay in the report, and the verdict's reasons say how many there were:
  "N difference(s) between a and b outside the rollout, judged by release mode".
